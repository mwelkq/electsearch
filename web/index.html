Алгоритм пошуку

Як працює пошук

Від сканування сайту до рекомендації сторінки в чаті. Етапи 1–2 — основна робота, етапи 3–4 — оформлення.

Етап 1

Crawler

Python-скрипт обходить сайт за посиланнями. Ліміт: 10 → 100+ сторінок

Етап 1

База сторінок

URL, заголовок і чистий текст кожної сторінки, збережені локально

Етап 2

Індекс

BM25лексичний: збіг слів
Embeddingsсемантичний: збіг змісту
Етап 2

RAG + LLM

Бере top-k сторінок з індексу, LLM формує відповідь і вибирає посилання

Етап 3

API

Бекенд на сервері, напр. FastAPI: POST /ask → відповідь + посилання

Етап 4

Чат-інтерфейс

Вікно на сайті факультету, де користувач пише питання

Експеримент: BM25 vs Embeddings

Однаковий набір тестових питань → порівняти, чи потрапляє правильна сторінка в top-3 (Precision@3, MRR). Зробити висновки, де який алгоритм кращий.

Приклад відмінності

«Коли сесія?» — BM25 шукає слово «сесія»; Embeddings знайде й сторінку «Графік екзаменів», навіть без цього слова.

Вибір LLM

Локально (напр. через Ollama) — безкоштовно й приватно; або через API — якісніше, але платно. Порівняти й обрати.

Чим можу допомогти?

Поставте питання звичайною мовою — я знайду потрібну сторінку на сайті факультету.
